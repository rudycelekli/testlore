# Paired native Codex measurement

Two independent authored specifications, two repetitions, both memory arms, seeded balanced order, maximum 24 role calls. Actual Codex CLI 0.155.1 used its configured default model; model version and provider randomness were unpinned. No API-key fallback was used. Frozen historical tests were independently validated; reference tests and three defects per specification were withheld from authors.

The no-memory arm caught 12/12 labeled defects across four successful trials. The memory arm caught 9/12 across three successful trials and one author timeout. Three completed pairs tied on recall. The failed pair contributes zero recall and remains in the summary. This is **inconclusive**, and does not establish a quality or speed benefit from memory. The timeout receipt records actual elapsed time beyond its requested timeout; host scheduling/suspension can delay process timers. No claim of a successfully enforced wall-clock budget is made for that trial.

All raw inputs, generated outputs, validations and labeled executions are retained. These are controlled public fixture sources, not private repository pilot results. Host home and temporary paths were redacted; original source and runner fingerprints remain opaque hashes. The manifest's Git revision records HEAD during a dirty development measurement, so it is not an exact-commit certificate. Each measured implementation file is preserved under `implementation/`, with bytes checked against the manifest's implementation hashes. These copies are provenance artifacts, not the current installed package.

The current evaluator additionally guards the entire source inventory before and after each worker call. The retained measurement used the earlier, weaker supplied-source/`test/` guard; its native Codex worker was instructed to use no tools. A side-effect regression now covers unreturned files under `tests/`.
