# ADR-003: Qualification before adoption claims

Status: Implemented contracts; live qualification results remain scoped. Date: September 30, 2026.

Real Git revisions, hypothetical input declarations, generated-test quality, agent-host compatibility and registry publication are separate evidence domains. Each retains raw outcomes and implementation identity. A successful unit test, SDK client, installed archive or historical result cannot stand in for another domain's execution.

Historical replay uses immutable commit pairs in disposable source copies, retains native discovery and selector results, and includes TestLore's complete span. Changed dependency/runtime identities reject comparisons that share installed dependencies. Deleted and renamed paths stay in the change inventory. Negative timings and missed or unexpected failures remain visible.

Mapping qualification operates on sealed review-only proposals in independent source copies. Hypothetical scope is explicitly labeled; reviewed observations do not establish all unexercised browser behavior. Full and selected execution must preserve native case identities and observed outcomes. Successful qualification does not apply a declaration or authorize permanent closed-world routing.

Paired learning freezes six authored evaluation contracts and distinct historical examples before the live worker run. Reference baselines, generated baselines and each defect repeat at least twice. Unstable, skipped, rejected or incomplete trials contribute no qualified detection. Call counts, JSON bytes and total time are resource measurements; provider billing remains unknown. Missing applicable memory is disclosed and prevents a general learning-effect claim.

Real host qualification records native MCP traffic, bounded output, process deadlines and executable/package identities. Tool discovery does not count as a call. Host approval rejection and authentication failure remain incomplete outcomes. No permission or credential changes are made to force a passing result.

Publication requires exact current main, the tested archive, protected workflow authority and actual npm ownership/publisher configuration. Read-only CLI diagnostics cannot verify CI OIDC authority. Source/host learning qualification and account authentication remain independent of release publication.
