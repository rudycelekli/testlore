# Bounded historical probes and green-suite regression repair

Status: Implementation candidate; exact-source and replay checks govern qualification
Date: 2026-10-11

## Decision

Separate public contribution metadata, executable historical bug recipes, approved current target contracts, module observations, native regression evidence, source repair, and reviewed outcome prioritization. A merged historical contribution cannot automatically become a verified recipe; a qualified recipe cannot establish current semantics; a reproduced module probe cannot authorize routing omissions or a source fix.

Retain exact original/fixed revisions, declared independent specifications, bounded probe cases, full explicit source/dependency closures, repeated named observations, and byte-bound qualification artifacts. Bundle a small reviewed public catalog without automatic execution. Plan current investigations read-only and require independently reviewed target expectations before module execution. Record approval provenance as a declaration, not authenticated truth.

Default approval is `pinned-source`: source changes invalidate applicability. `follow-contract` is a separate explicit decision to apply a hash-bound recipe and expectation across source revisions and refactors. Each run still binds current source, and older reports become stale. Preliminary identifier matching is advisory, not semantic proof.

For originally green suites, allow only a narrow standalone Node repair profile. Create a disposable detached worktree, run the complete original native suite twice, add exactly a contract-derived new regression, and demonstrate repeated failures corresponding to the module probe while preserving original named cases and outcomes. Commit tested regression bytes with hooks disabled, then delegate the existing source-only repair architecture, author and independent reviewer flow. Preserve original assertions, requirements, configuration, dependencies and the caller; freeze report, proposal and enabled knowledge at worker boundaries. Accept only repeated native success and an exact original-base diff containing the new regression and approved production module. The API prepares local artifacts; publication uses the existing verified PR pipeline and never merges.

Separate change-driven investigation from model autofix. Installation writes reviewable configuration and workflows, not a daemon or implicit recurring job. Investigation requires tracked bound artifacts and an exact reviewed TestLore SHA, runs on trusted default-branch pushes/dispatch with read-only permissions, and retains incomplete attempts. Agent autofix requires explicit worker/source configuration and a trusted authenticated self-hosted runner; it is separately opted in and may incur model cost. No privileged fork execution is introduced.

Outcome receipts are local, sealed, append-only and deduplicated by executed observation identity. Keep original observations separate from reviewer dispositions; `useful` requires reproduced evidence. Retain historical advisory signals after source changes with explicit staleness, quarantine missing/corrupt evidence, and record declared cost as unverified. Prioritization exposes uncertainty and budget estimates without suppressing recipes globally, granting acceptance authority, or asserting causal improvement. Declared test associations produce mapping proposals only; independent full/subset qualification remains necessary before omissions.

## Qualification

Challenge malformed and resealed claims, unsupported imports, incomplete closures, symlinks, stale contracts, unstable named outcomes, deadlines, worker/report mutation, weakened or manufactured oracles, duplicate dispositions, and original-input preservation. Test with actual subprocess execution and unchanged native assertions. Controller transport checks with deterministic workers are distinct from live-model qualification.

The public replay qualifies three historical module fault/fix pairs and exercises two compatible independent target modules plus one incompatible direct-fork control. It demonstrates no fresh target bug, runtime advantage, full upstream-suite qualification or AI learning benefit. Frozen constructed specifications are now observed data. Promotion requires new protected independent specifications, genuinely demonstrated application regressions, equal-budget agent comparisons, complete native outcomes, false-positive/timeouts, measured total cost and human oversight. Preserve negative results and rollback.

## Consequences

Contracts and explicit module closures require review; arbitrary repositories are not automatically supported. Conservative abstention is a valid outcome. The workflow can discover a missing regression before repair while preventing an agent from replacing good assertions, but cannot guarantee a useful fix on every run. Installation-to-observation, observation-to-native-regression, repair-to-reviewed-PR, and learning promotion remain separately measurable stages.
