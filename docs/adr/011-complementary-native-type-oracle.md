# 011: Complementary native type verification

Accepted for the initial single-project TypeScript profile.

## Problem and decision

Runtime-green receipts can hide declared type-contract failures. Routing already reasons about type dependencies, but that analysis does not execute the compiler. Add an installed project-local TypeScript oracle alongside native runtime verification and explicit independent behavioral challenges. Setup recommends it from static project fit and preserves explicit choices.

Keep native cases/history/comparisons separate. Overall failure or incompleteness includes the requested compiler check. Bind full ignored-source/dependency bytes, declared configuration, actual Node and producer closure before planning/native execution and after all callbacks. Only the original opaque opening object carries the cross-window binding; serialized evidence is display data. The oracle forces no emission and rejects unsupported/incomplete scope rather than claiming broad coverage.

## Verification and consequences

Independent development specifications predate the first component evaluation. Their ordinary runtime assertions miss five seeded type defects; the original compiler detects them. Retain healthy controls, all repeat exposures, exact input hashes, unsupported reference evidence and controller cost. Challenge the evaluator with malformed diagnostics, no-check sources, reserved inputs, service callback drift, ignored native-input mutation, copied opening tokens and contradictory persisted reports.

This adds execution and hashing cost. It supplies no omission authority, universal defect recall, learning promotion or overall competitive ranking. Project-reference builds and external symlinked dependency layouts need separate qualification. Source repair must satisfy enabled checks before authenticated application/publication; a requested but unqualified check cannot be silently ignored.
