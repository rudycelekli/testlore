# Reproducible measured-quality proof

`scripts/quality-proof.js` executes installed **c8** and **Stryker** on a disposable, deterministic Node fixture. It does not manufacture coverage or mutation JSON. Before either command runs, it captures the same provenance implementation used by the evidence-ingestion API. Report files and Stryker workspaces remain under excluded `.tddswarm` metadata, so measurement cannot quietly rebind changed source.

After each real tool finishes, the script imports its report with `ingestQuality`. It verifies nonzero coverage, one covered function out of two, nonzero killed mutants, nonzero surviving mutants, and complete mutation results. The uncovered `unused` function is intentional: its surviving mutants demonstrate that imported quality can expose a test gap. The script then changes the source, confirms both existing metrics become unmeasured, and confirms both old raw reports are rejected when imported with their original provenance.

From a repository checkout with the pinned development dependencies installed:

```sh
npm ci
node scripts/quality-proof.js --output benchmarks/quality/c8-stryker.receipt.json
```

For a separate API checkout or installed tool location:

```sh
node scripts/quality-proof.js --api-root /path/to/tddswarm --tools-root /path/to/tddswarm --output /path/to/receipt.json
```

`TDDSWARM_API_ROOT` and `TDDSWARM_TOOLS_ROOT` provide equivalent defaults. Tool versions come from the installed packages. Tool subprocesses receive argv directly; Stryker's trusted fixture configuration uses its actual command runner with the constant command `node --test test/classify.test.js`. Missing tools, failed commands, zero/incomplete metrics, or a failed provenance check cause a nonzero exit. The script does not download packages or fabricate fallback reports.

The checked-in [real-tool receipt](../benchmarks/quality/c8-stryker.receipt.json) records Node 22.19.0, c8 12.0.0, and Stryker 10.0.0. It observed 6/8 covered lines, 1/2 covered functions, 11 killed and 2 surviving mutants, a mutation score of 84.615%, and successful source-drift rejection. These results describe this fixture, not a production repository or an AI model. The receipt includes fixture source and tests, Stryker configuration, pre-run source digests, commands, stdout/stderr, imported records, actual raw reports, and stale-evidence checks.

Absolute machine paths are replaced with `<fixture>`, `<tools>`, `<api>`, `<repository>`, and `<node>`. `originalReportHash` identifies the original tool output before sanitization; the embedded sanitized raw report has different bytes when it contained absolute paths. Original report hashes are attestations for this execution, not a claim that the sanitized JSON retains the same digest. Times and generated mutant identifiers can vary between executions; the script checks meaningful counters rather than comparing generated bytes.

The [synthetic held-out receipt](../benchmarks/quality/generated-defects.receipt.json) comes from `scripts/generated-defects.js`. Its positive control catches all four independently demonstrated defects, while same-name vacuous tests catch none and fail acceptance. Commands and per-case outcomes are preserved with temporary machine paths sanitized. This is an offline validator control, with no model invocation or Agentic QE efficacy claim. See [candidate validation](candidates.md) for evaluating a separately supplied hidden corpus against actual frozen generated candidates.
