# Explain child-process dependency gaps

`testlore mappings` now connects a registration fixture's lexical state candidates, a literal file URL passed as process arguments, its imported implementation and source-bound test candidates. `--json` retains source spans, hashes, unresolved inputs and the producer binding. This helps developers review the process boundary that keeps their suite in full fallback.

These are static candidates. Importing a helper does not prove that a test launches the child; an imported function accepting an argument object may do nothing. TestLore therefore keeps `consumers: []` until execution is independently established. It distinguishes candidates in the native inventory from candidates outside it, and retains every existing graph warning. It applies no mapping and grants no omission authority.

Inherited environment, spread process options, dynamic arguments, cwd, installed implementations and shared state require independent evidence. Runtime and input hashes supplied to the API bind caller receipts; they do not establish truthful or complete effective inputs. Source/producer/graph/input drift rejects reuse. Analysis has finite source, output and aggregate syntax budgets; unavailable diagnostics preserve ordinary mapping suggestions and full fallback.

```sh
testlore mappings
testlore mappings --json
```

`processRegistrationProposals(graph, bindings)` diagnoses a caller-provided fresh graph. `validateProcessRegistrationProposals(report, graph, bindings)` recomputes it without executing native configuration or project commands. `inspectProcessRegistrationProposalEnvelope(report, sourceHashes)` checks only the envelope, authority and current source bindings. Envelope validity is explicitly distinct from semantic revalidation and qualification.
