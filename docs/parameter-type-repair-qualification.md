# Parameter identities, type dependencies and repair trials

These three engineering lanes have separate acceptance gates. Better evidence
collection does not establish a routing speedup or a learning improvement.

## Parameter identity

Duplicate titles can describe different inputs or parser implementations. A
native task ID links collection and results within one run; registration order
does not prove that two runs exercised the same parameters.

The reviewed `unimport` profile binds the original parser-factory source and its
individual invocation declarations. Runtime metadata ties the actual parser
callback reference and label to that declaration, then binds each child test.
The two `oxc` labels remain separate because their original parser closures are
different source declarations. This is an explicit, pinned observational
profile, not a general serializer for arbitrary functions.

All original titles and assertion bodies remain intact. The reporter checks
collection, terminal results, source freshness, registration completeness and
errors. Independent raw JSON outcome multiplicities must agree with the native
capture. Missing, stale or ambiguous evidence rejects the comparison. These
identities do not authorize any test omission or establish parser equivalence.

Ordinary execution also requires the exact reviewed standalone observer
configuration when this profile is requested. It binds the selected native
scope and checks raw outcome multiplicities against the case capture. An
unsupported explicit profile fails closed instead of silently returning an
uninstrumented complete result. Conservative routing remains unchanged.

The final frozen local profile ran all 254 original `unimport` cases, including
36 source-bound factory registrations. Native and TestLore captures agreed on
healthy runs and both seeded failures. A smaller manually chosen subset was
rejected because it omitted the `dts` failure. Those earlier observations did not qualify omissions. The newer bounded
[original application comparison](qualified-routing-repair-gates.md) executes
200 cases across23files, omits5files, and preserves both seeded failures across
healthy/fault/restored repetitions. It is substantially slower than full/native
execution; only the exact reviewed environment and fixture states qualify.

## Type-dependency precision

TestLore retains every import in the impact graph, including type imports, so a
changed type source can still select its consumers. A separate runtime-edge
analysis records whole-declaration type hints. Inline type specifiers, mixed
imports, runtime alternatives, prior runtime edges, declared inputs and observed
dependencies remain conservative.

The hints are **not omission authority**. Without private live admission, warning classification uses
the complete impact graph. The separately qualified original unimport runtime
uses native type erasure to refine runtime uncertainty while retaining every
impact edge. Native canaries are necessary evidence about a
particular transform, but cannot certify arbitrary plugins or typechecker reads.
An admitted precision profile still needs fresh internal bindings for effective
configuration, runtime implementations, transforms, project membership and
execution freshness, plus independently executed regression challenges.

Analysis cache version 2 binds runtime hints to the source and parser identity.
Malformed or obsolete persisted entries reparse. Legacy native summaries without
runtime hints retain all imports. Neither cache hits nor caller-supplied
qualification fields authorize omissions.

## Paired repair trials

Freeze independently maintained specifications, original native assertions,
historical defect revisions and evaluation budgets before requesting repairs.
Withhold the original fix and evaluation outcomes from the agent. Run memory and
no-memory arms under identical budgets with rotated order and repeated native
verification. Count timeouts, invalid proposals and failed repairs in the result.

A runner that never started is not a demonstrated defect. An adapted assertion
shim is not an unchanged original upstream suite. Retrieval accuracy is a
separate metric from successful repair. Previously inspected contracts become
development or regression data and cannot be advertised as fresh holdouts.

Promotion requires repeated evidence of better defect detection or efficiency.
Token usage, elapsed time and unavailable billing attribution must be reported
separately. Learning remains advisory until that gate passes.

`scripts/paired-repair-trials.js` is an explicit private pilot for one historical
`lukeed/klona` defect. It runs the original UVU assertions on Node 12.22.12, with
strict unhandled-rejection handling and ESM cache disabled equally in every arm.
Native processes use an isolated home and empty npm configuration; only the
audited subscription worker uses existing host authentication. The pilot binds
source, original assertion identities, dependencies and controller code before
agent requests, and verifies accepted proposals against the full native suite
twice. This historical source-only intervention is narrower than the complete
parent tree. Its generated installation lock is not an original upstream lock.
Two repetitions of one defect remain a clustered pilot, not independent
evidence of general repair quality or learning improvement.

The October 12 pilot completed four counterbalanced attempts and 12 audited
subscription role calls, with no retries or tool attempts. Each arm produced one
review-accepted repair and one review rejection. Both accepted repairs passed
all 137 original cases twice. All four authors produced identical source bytes;
blinded reviewers received identical semantic inputs but returned different
decisions. This is evidence of review variability, not a memory-assisted repair
improvement. Memory retrieved generic assertion metadata whose relevance to
this cloning defect remains unestablished.

Worker-reported usage was 234,613 input and 5,405 output tokens; billing and
provider model identity were unavailable. The retained evidence includes actual
worker inputs, outputs and transport audits, plus native stdout, stderr and
passive outcome receipts. Full provider event streams were not retained.
Learning remains advisory, and passing the original suite alone does not
establish that a repair preserves every undocumented behavior.

A separately recorded post-evaluation native probe reproduced a regression
identified by two reviewers: a constructor with an enumerable, non-writable
property clones successfully under both historical sources, but the shared
candidate throws a `TypeError`. Neither accepted candidate is eligible for
promotion as a regression-free repair. The frozen original-suite scores remain
recorded separately; this additional case is development evidence for future
evaluation, not a retrospectively added holdout or a learning gain.

The native lifecycle used by the identity reporter is described in
[Vitest's reporter API](https://vitest.dev/api/advanced/reporters.html).
[TypeScript's verbatim module documentation](https://www.typescriptlang.org/tsconfig/verbatimModuleSyntax.html)
explains why declaration and inline type syntax must be treated separately;
the effective application transform must still be measured.
