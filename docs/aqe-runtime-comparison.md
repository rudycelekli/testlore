# Agentic QE plus TestLore: a preregistered runtime comparison

This assay measures what executable validation contributes to **the same Agentic QE drafts**. It does not claim that TestLore is a better author, that template generation represents paid or free model quality, or that AQE's other workflows lack executable validation. Both arms receive identical source context and exactly the same generated bytes. A filter cannot make those bytes catch more bugs; its possible contribution is withholding unsafe promotion and making reasons actionable, with explicitly measured overhead.

The published release is pinned to **Agentic QE 3.14.8**, with npm integrity in the [manifest](../benchmarks/aqe-comparison/is-number-whitespace-v1/manifest.json). Its upstream tag points to **`4b0b91a300a12d3645f8344929d2e57f31c706e4`**. The main branch inspected on October 9, 2026 was `c8bc4eec83b68e8599c4b2aba533fc2aa7e53eb8`, which is a different source identity. No runtime result is attributed to main merely because a published version exists.

Primary source: [published tag's CLI generation contract](https://github.com/proffesor-for-testing/agentic-qe/blob/4b0b91a300a12d3645f8344929d2e57f31c706e4/src/cli/commands/test.ts). The CLI's own quality gate can reject drafts. Passing scores and estimated coverage are retained as upstream observations; independent native outcomes determine whether the measured candidate runs and catches the held-out defect.

## Frozen independent challenge

The new unit is maintainer-authored `jonschlinkert/is-number` [issue #3's genuine fix](https://github.com/jonschlinkert/is-number/commit/12749e3c411750f754d50f093471234c7ab270b0), compared with its first parent `204c885659b8ee1946534c61db91603b9a16d661`. The complete original source, tests, package declaration, README and license are archived with SHA-256 and Git blob identities. This specification was not in TestLore's earlier generation cohorts. That disjointness does not prove semantic independence, provider-training secrecy or a trusted timestamp.

The executable oracle selects the maintainer's two deterministic whitespace-only table entries and preserves the exact `assert.equal(isNumber(num), false);` assertion body. It adapts Mocha/import entry points and deterministic case titles before generation. The entire historical test also includes random values and timestamps; this assay explicitly qualifies the two issue #3 cases, not the entire upstream Mocha environment. Original archived bytes never change. `kind-of@3.0.2` is pinned within the original `^3.0.2` dependency declaration; its lockfile is retained by the runner.

The generator sees fixed source and the existing selected contract tests. It never receives the historical parent source or evaluation script. The parent challenge is not selected or edited after seeing drafts. Existing contract tests remain intact. No human or model reviewer is fabricated: the composition runs a declared automatic executable assay using independent maintainer contracts.

## Equal budgets and separate measurements

Two independent AQE generation repetitions each have one bounded CLI invocation, 120 seconds, no retries and no passed provider credentials. The adapter's capability probe, source snapshot, actual generation, output parsing and retention are included in generation timing. Both arms share each resulting candidate identity; the composition is not given additional author calls or hidden repairs.

Each draft runs twice on fixed source and twice on the historical parent with a ten-second execution limit. The maintainer oracle separately demonstrates fixed pass/parent failure twice. Defect detection requires named assertion failures, not syntax errors, imports failing or `<file-load>` failures. Stable identities and outcomes matter. TestLore's existing `stagePatch`/`validateCandidates` path then checks preservation of original cases and the independently demonstrated defect in disposable file copies. This file isolation is not a security sandbox; only pinned, trusted upstream code belongs in the campaign.

The report separates:

- generation rejection and timeout, candidate bytes and upstream quality evidence;
- candidate-only native stability and defect detection;
- composition acceptance/rejection and reasons;
- generation, common evaluation, composition validation and campaign wall time;
- unknown provider currency/token counts, which remain `null` rather than invented zero costs.

No live model provider is configured. Retrieval or learning is not evaluated. Candidate filtering alone cannot establish increased defect detection. Installation and preparation are separately identified as excluded from per-candidate runtime; an installation-to-result claim must include them.

## Run in a fresh hosted environment

After `npm ci` for TestLore, install AQE and the historical dependency into an isolated directory. Empty HOME/TMPDIR/npm configuration must be supplied by the host; never copy personal credentials. Preserve the generated installation lock and installation logs.

```sh
mkdir aqe-runtime
cd aqe-runtime
npm init -y
npm install --save-exact agentic-qe@3.14.8 kind-of@3.0.2
cd ..
node scripts/aqe-comparison.js \
  --aqe-package "$PWD/aqe-runtime/node_modules/agentic-qe" \
  --dependency-directory "$PWD/aqe-runtime/node_modules" \
  --output "$PWD/aqe-comparison-new"
```

A successful script exit means the bounded comparison was collected, even if both drafts were rejected or no advantage was demonstrated. Retain all repetitions, stderr/errors and the preregistration. The manifest currently covers one defect and two repetitions. That is a limited composition assay, not a public leaderboard or gold-standard qualification.

## Bootstrap observations (October 9)

The first hosted attempt stopped before installation because the dependency-free bootstrap omitted its `node:path` import. The second installed both exact distributions but rejected the executable declaration: npm's registry metadata reported `dist/cli/bundle.js`, while the integrity-verified tarball contains `./dist/cli/bundle.js`. Both spellings resolve to the same pinned relative entry point; the runner now admits those two exact spellings. Neither attempt executed generation or established a quality improvement. The installed lock and inventory are retained in the [second run](https://github.com/rudycelekli/testlore/actions/runs/37945888316).
